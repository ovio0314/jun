# CLAUDE.md — 전표 검토 도우미

회계팀 전표 검토 공수를 줄이는 **로컬 전용** 내부 도구. 영림원 ERP 전표조건검색 엑셀을 읽어 전표별 검사 결과를 보여준다.

## 데이터 비공개 원칙 (최우선)
- 실제 전표·증빙·검사 결과·저장 파일·로그는 **절대 커밋하지 않는다**. `input/`, `output/`, `local_data/`, `*.xlsx`, `*.csv`, `*.log`는 `.gitignore` 대상이다.
- 실데이터를 테스트 코드, 픽스처, 로그, 커밋 메시지, PR, 이슈에 복제하지 않는다. 테스트는 `sample_data/make_synthetic.py`의 익명 합성 데이터만 쓴다.
- 외부 AI/OCR/API를 호출하지 않는다. 서버는 `127.0.0.1:8501`만 사용하며 인터넷 공개 배포나 이메일 발송은 하지 않는다.
- 원본 엑셀은 읽기만 한다. 수정·이동·삭제하지 않는다. 초기화는 세션만 비운다.
- 실제 파일 대조는 `python -m voucher.verify <파일>`을 쓴다. 이 도구는 집계값만 출력하며, 그 출력에도 전표 내용을 넣지 않는다.

## 하지 않는 기능
자동 분개 수정, 결재·반려, ERP 쓰기, 중복 행 자동 삭제.

## 핵심 업무 규칙
- 전표 키 = 회계단위 + 전표관리단위 + 기표번호. 전표기표번호는 분개 행 식별자다. 기표번호가 비면 행마다 별도 키로 두고 묶지 않는다. 원본 엑셀 행번호(`_엑셀행`)를 유지한다.
- 번호·계정과목코드·사업자번호는 문자열로 다룬다. 공백 정리 전 원본은 `LoadResult.raw`에 둔다.
- 금액은 `Decimal`로 계산한다. 해석 불가 값은 0으로 대체하지 않고 오류로 남긴다. 빈 금액은 합계에서 0으로 보되 상태는 보존한다. 음수는 오류가 아니다. 외화 금액은 원화 합계에 더하지 않는다.
- 파일첨부여부는 문자열 TRUE/FALSE·불리언·빈값을 구분한다. FALSE를 증빙 누락으로 판정하지 않고 "ERP 첨부 표시 FALSE, 다우오피스 증빙 미확인"으로 표시한다. `증빙` 열 텍스트도 첨부 증거가 아니다.
- 관리항목 열의 의미는 계정마다 다르다. 관리항목2를 공급가액으로 가정하지 않고, 사용자가 계정별로 매핑한 경우에만 쓴다.
- 합계 불일치는 "차대변 불일치 또는 추출 누락 확인"으로 안내한다. 필터된 불완전 전표일 수 있기 때문이다.
- 계정 검사는 회사가 승인한 규칙(설정)으로만 한다. 규칙이 없으면 **미검사**다. 거래처만으로 계정을 확정하지 않는다. 예시 규칙은 합성 데이터용이며 기본 비활성이다.
- 부가세 계산 점검은 공급가액 열·일반과세 증빙 유형·반올림 기준이 모두 설정된 경우에만 한다. 불공제·영세율·면세·수정·분할은 일반과세로 판정하지 않고 해당 없음으로 둔다. '전표 내부 계산 점검'과 '실제 증빙 대조'를 구분한다.
- 적요는 빈칸과 사용자가 설정한 필수 정보만 점검한다. 글자 수로 적정성을 단정하지 않는다.
- 증빙 연결은 전표 키 또는 결재문서 ID 기준이다. 거래처+금액 일치는 후보일 뿐이다. 증빙 미제공, 연결 실패, 인식 실패, 확인 전 OCR 값은 모두 미검사로 둔다.
- 상태: 통과 / 오류 / 확인 필요 / 미검사 / 해당 없음. 요약은 오류 > 확인 필요 > 미검사 > 설정된 검사 통과 순이다. 다섯 영역이 모두 필수이며, 검사 통과는 최종 회계 적정성 보증이 아니다. 기준 없는 비교 값은 만들지 않는다.
- 검토상태·메모·검토자·검토일시는 자동 검사와 분리한다. 검사 실행으로 검토완료가 되지 않는다. 내용 해시가 바뀐 전표는 검토완료를 승계하지 않고 '미검토'로 되돌린 뒤 변경 표시를 한다.
- 엑셀 출력은 `export.safe_cell`로 수식 주입을 막는다.
- 화면 수치는 모두 파일에서 계산한다. 1,224행, 276건, 750~800건 같은 참고값을 하드코딩하지 않으며, 파일 전표 수와 업무상 검토 건수를 같은 모집단으로 가정하지 않는다.

## 구조
- `voucher/`: 파서(`parser`), 계정 현황(`accounts`), 규칙 엔진(`checks`), 설정(`settings`), 증빙 인터페이스(`evidence`), 검토·저장(`review`), 출력(`export`), 계정 질문(`qa`), 건수 대조(`verify`)
- `ui/`: Streamlit 화면. `app.py`가 진입점이다.
- 성능: 넓은 DataFrame에서 그룹마다 `to_dict`를 호출하면 pandas 3에서 매우 느리다. `checks.group_records`처럼 레코드 변환은 한 번만 한다.
- 상태를 바꾸는 버튼은 `ui.common.flash_and_rerun`으로 다시 그린다. 앞서 그린 탭에 옛 값이 남는 것을 막기 위해서다.

## 브라우저판 (`browser/`)
- `browser/src/engine.js`는 `voucher/`의 규칙을 JavaScript로 옮긴 것이다. **규칙을 바꾸면 양쪽을 함께 고치고** `tests/test_browser_parity.py`로 결과가 같은지 확인한다.
- `browser/src/*`을 고친 뒤에는 `cd browser && npm run build`로 `dist/전표검토.html`을 다시 만들어 커밋한다. 빌드가 최신인지는 테스트가 검사한다.
- 배포 HTML은 CSP `connect-src 'none'`로 외부 전송을 막는다. `unsafe-eval`이나 외부 스크립트·CDN을 추가하지 않는다.
- 화면에 넣는 모든 값은 `esc()`로 이스케이프한다. 파일 내용이 HTML로 해석되지 않게 하기 위해서다.
