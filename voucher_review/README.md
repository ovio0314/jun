# 전표 검토 도우미 (1차)

회계팀 전표 검토 공수를 줄이기 위한 **로컬 전용** 내부 도구입니다. 영림원 ERP 전표조건검색 엑셀을 올리면 전표별 검사 결과를 보여 줍니다.

- 외부 AI·OCR·API를 호출하지 않습니다. 서버는 `127.0.0.1:8501`만 사용합니다.
- 자동 분개 수정, 결재·반려, ERP 쓰기 기능은 **없습니다**.
- 검사 통과는 설정된 기준에 대한 결과일 뿐이며, 최종 회계 적정성을 보증하지 않습니다.

> **검증 상태:** 실제 파일 `input/9월 전표 내역.xlsx`는 개발 환경에 없어 **실제 파일 검증은 하지 않았습니다.**
> 알려 주신 46개 열 구조(첫 행 제목, 둘째 행 헤더)로 만든 익명 합성 데이터로만 테스트했습니다.
> 실제 파일은 아래 [실제 파일 건수 대조](#실제-파일-건수-대조)로 확인해 주세요.

## 가장 쉬운 방법: 브라우저판 (설치 없음)

`browser/dist/전표검토.html` 파일 **하나만** 있으면 됩니다. Python이나 다른 프로그램을 설치할 필요가 없습니다.

1. `전표검토.html`을 PC에 저장하고 더블클릭합니다. 크롬이나 엣지에서 열립니다.
2. 왼쪽 **📂 엑셀 파일 선택**으로 `9월 전표 내역.xlsx`를 고릅니다.
3. **불러오기**, 이어서 **검사 실행**을 누릅니다.

- **인터넷 연결이 필요 없습니다.** 필요한 라이브러리가 모두 파일 안에 들어 있습니다.
- 페이지 보안 설정(Content-Security-Policy `connect-src 'none'`)으로 **외부 전송을 원천 차단**합니다. 엑셀 내용은 이 PC의 브라우저 안에서만 처리됩니다.
- 기능은 Python판과 같습니다: 전표 검사(5개 영역), 필터, 상세, 검토 메모, 증빙 수기 연결, 결과 엑셀 4시트, 계정 질문하기, 계정과목 현황, 검사 설정, 저장·불러오기.
- 검사 규칙은 Python판과 동일한 결과를 내도록 옮겼고, 자동 테스트(`tests/test_browser_parity.py`)로 두 엔진의 결과가 같은지 대조합니다.

Python판과 다른 점:

| 항목 | 브라우저판 |
|---|---|
| 파일 선택 | input 폴더 대신 화면에서 직접 선택 |
| 저장 | 이 브라우저 안(IndexedDB)에 저장. 브라우저 사용 기록을 지우면 사라질 수 있으니 **작업 파일로 내보내기(.json)**로 따로 보관하세요 |
| 설정·회사 가이드 | 이 브라우저의 localStorage에 저장. 설정 파일로 내보내기/가져오기 가능 |
| 원본 SHA-256 | Chromium의 file:// 에서 계산됨을 확인. 브라우저가 막으면 빈칸이 될 수 있음(검사 결과에는 영향 없음) |

개발자용:
```bash
cd browser && npm install && npm run build   # dist/전표검토.html 재생성
npm test                                     # JS 단위 테스트
```
- 사용 라이브러리: exceljs 4.4.0, big.js 6.2.2 (MIT). 모두 npm에서 받아 파일 안에 넣었습니다.
- `npm audit`는 exceljs가 쓰는 `uuid`의 moderate 경고를 1건 보고합니다(GHSA-w5hq-g745-h8pq, v3/v5/v6에 버퍼를 넘길 때만 해당). 이 도구는 그 경로를 쓰지 않습니다.
- 브라우저판에서 확인한 동작: Chromium(Playwright)으로 `file://`에서 열어 불러오기, 검사, 증빙 연결, 메모, 결과·계정현황 다운로드, 설정 적용·저장, 브라우저 저장·재열기·이어받기·삭제, 초기화를 확인했고 외부 요청은 0건이었습니다.
- **Windows의 실제 크롬·엣지에서는 직접 확인하지 못했습니다.**

## Windows 설치·실행 (Python판)

1. **Python 3.11 이상 설치** — python.org에서 설치합니다. 설치 화면에서 "Add python.exe to PATH"를 체크하세요.
2. **최초 설치** — `voucher_review` 폴더의 `setup_windows.bat`을 더블클릭합니다. `.venv`를 만들고 `requirements.txt`의 고정 버전을 설치합니다.
3. **실행** — `run_windows.bat`을 더블클릭합니다. 브라우저에서 http://127.0.0.1:8501 을 엽니다.
   - 종료는 검은 창에서 `Ctrl+C`를 누르거나 창을 닫습니다.
4. **실제 파일 위치** — `voucher_review\input\` 또는 저장소 루트 `input\`에 둡니다(예: `input\9월 전표 내역.xlsx`). 사이드바에서 선택하거나 직접 업로드할 수 있습니다.
5. **테스트** — `test_windows.bat`을 실행합니다(합성 데이터만 사용).

> 배치 파일은 Linux에서 작성했고 **Windows에서 직접 실행해 보지는 않았습니다.** 실행되지 않으면 명령 프롬프트에서 아래 명령을 직접 입력하세요.

명령 프롬프트로 직접 실행할 때:
```bat
cd voucher_review
py -3.11 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python -m streamlit run app.py
.venv\Scripts\python -m pytest -q
.venv\Scripts\python -m voucher.verify "input\9월 전표 내역.xlsx"
```

macOS/Linux:
```bash
cd voucher_review
pip install -r requirements.txt
streamlit run app.py
python -m pytest -q
```

## 사용 절차

### 1. 불러오기
사이드바에서 파일을 올리거나 input 폴더 파일을 고릅니다.
1. **시트/헤더 행 선택** — 여러 시트 중 헤더 후보를 찾아 보여 줍니다.
2. **열 매핑 확인** — 자동 인식된 열을 확인하고 필요하면 바꿉니다.
3. **불러오기** — 필수 열 누락, 필수 열 중복, 읽을 수 없는 파일은 한글 메시지로 안내합니다.

### 2. 검사
**검사 실행**을 누르면 검사가 돌지만, 검토상태는 바뀌지 않습니다.
- **🔍 전표 검사** 탭
  - 요약: 원본 행 수, 전표 수, 오류 / 확인 필요 / 미검사 / 설정된 검사 통과 건수. 네 상태의 합은 항상 전표 수와 같습니다.
  - 필터: 회계일, 기표부서, 기표자, 결재상태, 전표유형, 검사결과, 검토상태. 초기값은 전체이고, 기본 정렬은 오류 우선입니다.
  - 목록: 전표마다 데이터 점검, 금액, 계정, 적요, 증빙 상태와 사유를 보여 줍니다.
  - 상세: 분개 전체, 관리항목 원본, 검사 근거, 검토상태·메모, 증빙 수기 등록과 연결.
- **⚙️ 검사 설정** 탭
  - 부가세 계정코드, 계정별 공급가액 열, 일반과세 증빙 유형, 특수 증빙 제외 키워드, 반올림 기준
  - 회사 승인 계정 규칙, 적요 규칙, 증빙 요구 기준
  - "설정 적용"은 이번 세션에만 적용하고, "이 PC에 저장"은 `local_data/settings.json`에 저장합니다.

### 3. 결과 다운로드
전표 검사 탭의 **검사 결과 엑셀 다운로드**를 누르면 네 시트가 담긴 파일을 받습니다.

| 시트 | 내용 |
|---|---|
| 전표요약 | 전표별 검사 상태, 검토상태·메모 |
| 검사상세 | 전표 키, 검사코드, 실제 값, 비교 값, 차이, 근거, 적용 규칙 버전, 원본 행번호 |
| 원본분개 | 원본 값 그대로 |
| 적용기준 | 적용한 설정과 규칙 버전 |

- 받기 전에 원본분개 행 수와 전표요약 건수를 자동으로 대조해 화면에 표시합니다.
- 텍스트 셀은 수식으로 실행되지 않게 막습니다.

### 4. 저장·재열기
**💾 저장·불러오기** 탭을 씁니다.
- **저장** — `local_data/saves/*.json`에 저장합니다. 전표 데이터, 검토 메모, 수기 증빙, 설정 스냅샷이 들어 있으므로 저장소에 올리지 않습니다.
- **재열기** — 원본 파일 없이 저장 당시 데이터와 설정으로 다시 검사합니다.
- **이어받기** — 새로 불러온 파일에 이전 검토상태와 증빙을 옮깁니다. 같은 전표 키라도 분개 내용이 바뀌면 검토완료를 승계하지 않고 **미검토 + 변경 표시**로 둡니다.

### 5. 초기화와 삭제
- **초기화**(사이드바)는 현재 세션만 비웁니다. 원본 엑셀, 저장 파일, 설정 파일은 지우지 않습니다.
- **저장 데이터 삭제**는 삭제할 파일을 고르고, 확인을 위해 파일 이름을 그대로 입력해야만 실행됩니다. 저장 폴더 밖의 파일은 삭제하지 않습니다.
- 저장된 회사 가이드는 설정 탭에서 확인란을 체크한 뒤 삭제합니다.

### 실제 파일 건수 대조
```
python -m voucher.verify "input/9월 전표 내역.xlsx"
```
- 원본 행 수를 파서와 별도로 openpyxl로 다시 셉니다.
- 전표 수, 기간, 차대변 불일치, 부가세 행, 적요 빈칸, 파일첨부여부 분포, 요약 4상태 합계, 다운로드 건수를 대조합니다.
- 집계값만 출력하고 전표 내용은 출력하지 않습니다.
- 참고값(1,224행 / 기표번호 276개 등)은 코드에 넣지 않았습니다. 이 출력과 직접 비교해 주세요.

## 검사 규칙 요약

| 영역 | 코드 | 내용 | 설정 전 기본 |
|---|---|---|---|
| 데이터 점검 | D01~D06 | D01 필수 값 누락 · D02 분개 식별자 중복 · D03 완전 동일 행 · D04 차대 동시 입력 · D05 금액 해석 불가 · D06 금액 없음. 자동 삭제하지 않음 | 수행 |
| 금액 검사 | A01 | 원화 차대 합계. 불일치는 "차대변 불일치 또는 추출 누락 확인" | 수행 |
| 금액 검사 | V01 | 부가세 **전표 내부 계산 점검** | **미검사**: 공급가액 열·일반과세 유형·반올림 기준을 모두 설정해야 수행 |
| 계정 검사 | C00~C02 | 회사 승인 규칙의 허용 계정과 필수 조합 | **미검사**: 규칙이 없으면 미검사. 예시 규칙은 비활성 |
| 적요 검사 | M00~M02 | 빈칸 점검(기본 오류) + 설정한 필수 적요 정보 | 빈칸만 점검 |
| 증빙 검사 | E00~E03 | 연결·확인된 세금계산서·품의서로 **실제 증빙 대조** | **미검사**: 증빙이 연결되지 않으면 미검사 |

- 요약은 오류 → 확인 필요 → 미검사 → 설정된 검사 통과 순으로 정합니다. 다섯 영역이 모두 필수이므로, 증빙이 연결되기 전에는 모든 전표가 최소 '미검사'로 남습니다.
- 특수 증빙(불공제·영세·면세·수정·분할 등, 부분 일치)은 일반과세로 판정하지 않고 '해당 없음'으로 둡니다.

### 데이터 처리 기준 (보수적 기본값)

| 항목 | 기준 |
|---|---|
| 헤더 인식 | 모든 시트 상단 30행에서 예상 열 이름이 5개 이상 일치하는 행을 후보로 제시합니다. 헤더 위 조회 조건 텍스트는 화면과 결과에 표시합니다 |
| 필수 열 | 회계단위, 전표관리단위, 기표번호, 계정과목코드, 계정과목, 차변금액, 대변금액 |
| 필수 값 (D01) | 기표번호, 회계일, 계정과목코드, 계정과목 |
| 전표 키 | 회계단위 + 전표관리단위 + 기표번호. 기표번호가 빈 행은 행마다 별도 키로 둡니다 |
| 금액 | Decimal. 쉼표, 공백, '원'은 제거합니다. 음수(`-`, `△`, `▲`, 괄호)는 허용하며 오류가 아닙니다. 해석 불가 값은 0으로 바꾸지 않고 오류로 둡니다 |
| 빈 금액 | 합계에서 0으로 봅니다. 빈값이었다는 상태는 따로 보존합니다 |
| 외화 | 원화 합계에 더하지 않습니다 |
| 파일첨부여부 | 문자열 TRUE/FALSE, 불리언, 빈값을 구분해 표시만 합니다. FALSE를 증빙 누락으로 판정하지 않습니다 |
| 관리항목 | 계정별로 의미가 다릅니다. 관리항목2는 공급가액 '후보'로 안내만 합니다 |
| 전표 대표값 | 기표자, 부서, 결재상태, 전표유형은 전표의 첫 유효값입니다(필터 기준) |
| 모집단 | 파일 전표 수와 업무상 약 750~800건(집계 기간 미확인)을 같은 모집단으로 가정하지 않습니다 |

## 1차 미구현 기능

- OCR, PDF·이미지 인식, 다우오피스·국세청 등 외부 연동 — 인터페이스만 설계했습니다([docs/evidence_interface.md](docs/evidence_interface.md)). 증빙은 전표 상세에서 수기로 등록합니다.
- 결재문서 ID 기반 자동 연결 — 로직(`auto_link`)은 있습니다. 하지만 현재 ERP 46개 열에 결재문서 ID가 없어 화면에 연결하지 않았습니다.
- OCR 추출값 확인 화면(원문 페이지·영역 보기, 확인·수정) — 모델만 있고 화면은 없습니다.
- 회사 승인 계정 규칙과 적요 규칙의 실제 내용 — 회계팀이 설정해야 합니다. 예시 규칙은 합성 데이터용이며 비활성입니다.
- 품의서 금액·기간과 전표 금액 비교 — 회사 기준이 없어 비교 값을 만들지 않았습니다.
- 다중 사용자 동시 편집, 권한 관리, 감사 로그
- 자동 분개 수정, 결재·반려, ERP 쓰기 — 범위 밖

## 계정 질문하기 · 계정과목 현황 (1단계 기능)

- **💬 계정 질문하기** — "공장 전기요금 낼 때 차변 대변 뭐 써요?" 같은 질문에 제조업 거래유형 47종 가이드로 참고 분개를 제시합니다. 불러온 파일에서 회사가 실제로 쓰는 계정코드와, 적요가 비슷한 과거 사례도 함께 보여 줍니다. 답변은 참고용이며 회사 승인 규칙이 아닙니다.
- **📋 계정과목 현황** — 차변·대변에 쓰인 계정 전체와 상대계정, 계정별 관리항목 사용 현황, 코드·계정명 불일치를 보여 줍니다.
- 가이드는 `voucher/data/manufacturing_guide.json`에 있습니다. 설정 탭에서 JSON을 받아 고친 뒤 올리면 `local_data/account_guide.json`에 저장됩니다.
