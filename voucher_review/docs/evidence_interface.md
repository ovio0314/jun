# 증빙 연결 인터페이스 설계 (2차 확장 준비)

구현 위치: `voucher/evidence.py`. 1차에서는 **수기 입력(ManualEvidenceStore)만 동작**합니다.
OCR, 다우오피스·국세청 등 외부 API 연동은 구현하지 않았습니다(`NotConnectedProvider` 자리표시자만 있음).

## 1. 원천값 모델

| 증빙 유형 | 필드 (`DOC_FIELDS`) | 검사 필수 필드 (`CHECK_FIELDS`) |
|---|---|---|
| 세금계산서 | 승인번호, 공급자사업자번호, 작성일, 공급가액, 세액, 합계, 출처 | 승인번호, 공급가액, 세액 |
| 품의서 | 문서번호, 승인상태, 목적, 금액, 기간시작, 기간종료 | 문서번호, 승인상태 |
| 계정해설 | 계정코드, 적용기준, 문서근거 | 계정코드, 적용기준 |

필드 값 하나는 `FieldValue`로 보관합니다.

| 속성 | 의미 |
|---|---|
| `value` | 값 (금액은 Decimal) |
| `source` | 수기입력 / OCR / 외부연동 / 파일가져오기 |
| `page`, `region` | 원문 페이지(1부터), 영역 `[x0, y0, x1, y1]` — OCR 값에 필수 |
| `confidence` | 인식 신뢰도 (참고용, 판정에 쓰지 않음) |
| `confirm_status` | 미확인 / 확인 / 수정확인 / 인식실패 |
| `confirmed_by`, `confirmed_at` | 수동 확인자·일시 |

`FieldValue.usable`이 참일 때만 검사에 사용합니다. OCR·연동 값은 기본 `미확인`이므로 사람이 확인하기 전에는 **미검사**가 됩니다.

`EvidenceDoc.file_name`은 참고용이며, **파일명만으로 첨부 적정성을 판단하지 않습니다.**

## 2. 연결 규칙 (`EvidenceLink`)

| 연결 방식 | 상태 | 검사 사용 |
|---|---|---|
| 전표키 (정확 일치) | 확정 | 사용 |
| 결재문서ID (정확 일치, `auto_link`) | 확정 | 사용 |
| 수동 (사용자가 전표 상세에서 연결) | 확정 | 사용 |
| 거래처+금액 (`suggest_by_partner_amount`) | **후보** | 사용 안 함 — 수동 확정(`confirm_candidate`) 필요 |
| 존재하지 않는 문서 | 연결실패 | 사용 안 함 |

거래처+금액이 같다는 이유만으로 자동 확정하지 않습니다. 애매한 경우는 수동 연결이 필요합니다.

## 3. 증빙 검사 판정 (`checks.check_evidence`)

- 요구 증빙: 부가세 행이 있는 전표 → 세금계산서, 모든 전표 → 품의서 (설정에서 변경 가능)
- 다음은 모두 **미검사**로 기록하며 `설정된 검사 통과`가 되지 않습니다.
  증빙 미제공, 후보만 있음, 연결 실패, 인식 실패, 필수 값 수동 확인 전
- ERP `파일첨부여부` FALSE는 증빙 누락 판정에 쓰지 않습니다. 근거에 "ERP 첨부 표시 FALSE, 다우오피스 증빙 미확인"으로 남깁니다.
- `증빙` 열 텍스트('세금계산서' 등)는 부가세 내부 계산의 유형 구분에만 쓰며, 실제 첨부 증거로 쓰지 않습니다.
- **전표 내부 계산 점검**(V01, 금액 검사)과 **실제 증빙 대조**(E01/E03, 증빙 검사)는 결과 근거에 구분해 표시합니다.
  - E01: 전표 부가세 행 합계와 세금계산서 세액 합계를 비교합니다.
  - E03: 전표 공급가액과 세금계산서 공급가액을 비교합니다. 공급가액 열 매핑이 없으면 미검사입니다.
  - E02: 품의서 승인 상태를 확인합니다. 품의 금액이나 기간은 회사 기준이 없으므로 비교하지 않습니다.

## 4. 2차 구현 시 할 일

1. `EvidenceProvider` 프로토콜(`list_docs`, `get_doc`)을 구현합니다.
   - 다우오피스 결재문서 조회: 결재문서 ID로 품의서·첨부 목록을 가져옵니다.
   - OCR 추출기: PDF/이미지 → `FieldValue(source=OCR, page, region, confirm_status=미확인)`
   - 국세청 전자세금계산서 조회: 승인번호 기준
2. ERP 전표에서 결재문서 ID를 얻는 경로를 확인해 `auto_link(approval_ids=...)`에 넘깁니다. 현재 46개 열에는 결재문서 ID 열이 없습니다.
3. 추출값 확인 화면을 만듭니다. 원문 페이지·영역을 보여 주고 확인·수정 버튼을 눌러 `confirm_status`를 갱신합니다.
4. 인증정보가 필요한 연동은 로컬 설정 파일로 관리하고 저장소에 올리지 않습니다.
